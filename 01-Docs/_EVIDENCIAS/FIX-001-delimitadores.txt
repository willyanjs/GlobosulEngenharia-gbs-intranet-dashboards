🔧 PROBLEMA IDENTIFICADO
========================

Issue: Delimitadores genéricos $ causando potencial conflito
- Função usava: AS $ ... $;
- Bloco DO usava: DO $ ... $;
- Risco: Parser PostgreSQL pode confundir os delimitadores

🎯 SOLUÇÃO APLICADA
===================

Substituído por delimitadores nominais distintos:

1. Função:
   ANTES: AS $ ... $;
   DEPOIS: AS $fn$ ... $fn$;
   
2. Bloco DO:
   ANTES: DO $ ... $;
   DEPOIS: DO $do$ ... $do$;

3. Timestamp:
   ANTES: NEW.updated_at := NOW();
   DEPOIS: NEW.updated_at := now();
   (Convenção PostgreSQL: funções built-in em lowercase)

✅ BENEFÍCIOS
=============

- Clareza: Delimitadores com nomes descritivos
- Segurança: Zero risco de conflito entre blocos
- Compatibilidade: PostgreSQL 9.0+ suporta delimitadores nominais
- Legibilidade: Código mais explícito e autodocumentado

📊 ESTRUTURA FINAL
==================

```sql
-- =====================================================
-- v1.0.2-HML — Bloco idempotente para função/trigger
-- =====================================================

-- Função: atualiza updated_at antes de UPDATE
CREATE OR REPLACE FUNCTION auth.update_usuarios_timestamp()
RETURNS trigger
LANGUAGE plpgsql
AS $fn$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END;
$fn$;

-- Ownership explícito
ALTER FUNCTION auth.update_usuarios_timestamp() OWNER TO gbs_dev;

-- Trigger: criar somente se ainda não existir
DO $do$
BEGIN
  IF NOT EXISTS (
    SELECT 1
    FROM pg_trigger
    WHERE tgname = 'trg_usuarios_updated_at'
      AND tgrelid = 'auth.usuarios'::regclass
  ) THEN
    CREATE TRIGGER trg_usuarios_updated_at
      BEFORE UPDATE ON auth.usuarios
      FOR EACH ROW
      EXECUTE FUNCTION auth.update_usuarios_timestamp();
  END IF;
END
$do$;
```

📝 NOTAS TÉCNICAS
=================

1. Delimitadores Nominais:
   - PostgreSQL permite qualquer string alfanumérica entre $
   - Exemplos válidos: $fn$, $function$, $body$, $do$, $block$
   - Recomendação: usar nomes curtos e descritivos

2. Convenções:
   - $fn$ = function (corpo da função)
   - $do$ = do block (bloco procedural)
   - $sql$ = sql statement (queries dinâmicas)

3. Compatibilidade:
   - PostgreSQL 9.0+: ✅ Suporte completo
   - PostgreSQL 8.4: ✅ Suporte completo
   - PostgreSQL 8.0: ✅ Introdução dos delimitadores nominais
