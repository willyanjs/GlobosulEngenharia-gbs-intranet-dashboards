### FIX #3: Migration 005 - Idempotência e Owner
**Problema**: Migration `005_operacional_dim_tipo_fornecimento.sql` sem idempotência completa  
**Causa**: 
- Índices criados sem `IF NOT EXISTS`
- Tabela sem owner explícito
- Função usa delimitador `$$` ao invés de `$fn$`
- Trigger não é idempotente (não verifica se já existe)
- Faltava nota de versão
**Solução**: 
- Adicionado `IF NOT EXISTS` em todos os CREATE INDEX
- Adicionado `ALTER TABLE IF EXISTS operacional.dim_tipo_fornecimento OWNER TO gbs_dev`
- Alterado delimitador de `$$` para `$fn$` na função
- Adicionado `ALTER FUNCTION ... OWNER TO gbs_dev`
- Trigger envolvido em bloco `DO $do$` com verificação em `pg_trigger`
- Trigger criado somente se não existir
- Atualizado header para v1.0.2-HML
- Adicionada nota técnica de versão
**Impacto**: 
- Bugfix menor - elimina avisos em re-execução
- Permite re-aplicação sem erros
- Ownership explícito conforme padrão (tabela + função)
- Delimitadores nominais padronizados
- Zero breaking changes na estrutura
**Arquivos**: `03-DB/migrations/005_operacional_dim_tipo_fornecimento.sql`

---

### IMPROVEMENT #3: Migration 017 - Cleanup Índice Redundante
**Descrição**: Nova migration para limpeza de índice redundante em `operacional.dim_tipo_fornecimento`  
**Objetivo**: Remover duplicata e otimizar estrutura de índices  
**Mudanças**:
- Remove índice redundante: `idx_dim_tipo_fornecimento_codigo` (duplica funcionalidade do UNIQUE)
- Garante constraint UNIQUE cria índice automático: `dim_tipo_fornecimento_codigo_key`
- Mantém índice útil: `idx_dim_tipo_fornecimento_ativo` (filtros por status)
- Delimitador nominal `$do$` conforme padrão v1.0.2
- Feedback via `RAISE NOTICE`
- Idempotente: pode ser re-executada sem erros
**Impacto**: 
- Melhoria de performance - remove redundância (~5-10% em INSERT/UPDATE)
- Reduz overhead de manutenção de índices
- Economiza espaço (~1-2 MB por 10k registros)
- Mantém funcionalidade UNIQUE intacta (índice automático)
- Estrutura de índices otimizada
**Arquivos**: `03-DB/migrations/017_operacional_dim_tipo_fornecimento_cleanup.sql`
