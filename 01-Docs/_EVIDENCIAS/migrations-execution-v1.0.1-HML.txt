========================================
PRÓXIMOS PASSOS (PARA EXECUTAR EM HML)
========================================

1. Definir DATABASE_URL com credenciais HML:
   export DATABASE_URL="postgresql://gbs_dev:senha@192.168.1.92:5432/gbs_intranet_prod"

2. Navegar para diretório de migrations:
   cd 03-DB

3. Executar script (Git Bash/WSL no Windows):
   bash apply_migrations.sh

4. Verificar código de saída:
   echo $?  # Deve retornar 0

5. Validar objetos criados:
   psql "$DATABASE_URL" -c "\dt auth.*; \dt operacional.*; \dt financeiro.*; \dv vw.*;"

6. Verificar que public está vazio:
   psql "$DATABASE_URL" -c "\dt public.*;"

7. Testar views:
   psql "$DATABASE_URL" -c "SELECT * FROM vw.vw_pipeline LIMIT 1;"
   psql "$DATABASE_URL" -c "SELECT * FROM vw.vw_fluxocaixa LIMIT 1;"

8. Validar permissões (gbs_app):
   psql "$DATABASE_URL" -c "SET ROLE gbs_app; SELECT * FROM vw.vw_pipeline LIMIT 1; RESET ROLE;"

9. Anexar log como evidência:
   cp logs/migrations.log ../01-Docs/_EVIDENCIAS/migrations-v1.0.1-HML.log

10. Atualizar CHANGELOG.md com status de execução:
    - CA-03, CA-04, CA-05: Marcar como CUMPRIDO
    - CT-01, CT-04, CT-05, CT-06: Marcar como APROVADO

========================================
COMANDOS DE TROUBLESHOOTING
========================================

# Se erro: CRLF (Windows)
dos2unix apply_migrations.sh
bash apply_migrations.sh

# Se erro: permissões (Linux)
chmod +x apply_migrations.sh
./apply_migrations.sh

# Se erro: roles não existem
psql "$DATABASE_URL" -c "
  CREATE ROLE gbs_admin WITH LOGIN PASSWORD 'senha' SUPERUSER;
  CREATE ROLE gbs_rw WITH LOGIN PASSWORD 'senha';
  CREATE ROLE gbs_ro WITH LOGIN PASSWORD 'senha';
  CREATE ROLE gbs_app WITH LOGIN PASSWORD 'senha';
  CREATE ROLE gbs_dev WITH LOGIN PASSWORD 'senha';
"

# Se erro: objetos em public
psql "$DATABASE_URL" -c "
  DROP SCHEMA public CASCADE;
  CREATE SCHEMA public;
  REVOKE ALL ON SCHEMA public FROM PUBLIC;
"

# Verificar log detalhado
cat logs/migrations.log
